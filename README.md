# 삼킴지킴이

React Native + Expo SDK 58 + TypeScript로 만든 식사 모니터링 프로토타입입니다.

## 새 디자인 (0.2.0)

`samkim keepr 2.pdf`의 25·28·30~40페이지 기준으로 화면을 개편했습니다.

- 25: 청록색 시작 화면, 이름 입력, 개인정보/장치 사용 동의
- 28: 오늘의 기록, 최근 식사, 모니터링 시작
- 30~32: 식사 종류·권한, 카메라 셀프 확인, 실시간 모니터링
- 33~36: 2초 발성 안내, 녹음 정리, 완료, 흡인 테스트 알림 팝업
- 37: 종료 버튼 (추가 요청에 따라 확인창 없이 바로 보고서로 이동)
- 38~39: 상세 식사 보고서, 흡인 알림 타임라인, 날짜별 목록·식사 종류 필터
- 40: 내 정보 수정, 권한 관리, 글자 크기, 데이터 관리

홈·모니터링·보고서·더보기의 네 개 하단 탭을 제공합니다. 탭 선택 시 반투명 블러 캡슐이 스프링 애니메이션으로 이동합니다. 기기의 동작 줄이기 설정이 켜져 있으면 즉시 전환합니다. 주요 버튼과 더보기 항목에는 짧은 누름 반응을 적용하고, 안내 팝업은 180ms 진입·120ms 종료 전환으로 표시합니다. 버튼 동작은 애니메이션 완료를 기다리지 않습니다. 실제 장치를 보여 주는 카메라 미리보기를 사용하며 PDF의 인물 사진은 앱에 포함하지 않았습니다. 실제 분석과 연결되지 않은 진단·안전 판정은 표시하지 않습니다.

## 실행

```sh
npm install
npm run web
```

localhost 주소를 브라우저에서 열고 카메라·마이크 권한을 허용하세요. 노트북의 기본 카메라와 마이크를 사용합니다. 외장 장치가 기본값이면 브라우저 사이트 권한에서 내장 장치를 선택하세요. 권한 요청에는 HTTPS 또는 localhost가 필요합니다.

휴대폰에서는 `npm start` 후 SDK 58을 지원하는 Expo Go 또는 개발 빌드로 실행하세요. `npm run ios` / `npm run android`도 제공합니다. 카메라는 실제 기기에서 확인하세요.

## 시연 순서

1. 이름 입력 → 두 가지 동의 → 시작
2. 식사 모니터링 시작 → 현재 시간에 맞춰 자동 선택된 식사 확인 (직접 변경 가능)
3. 카메라/마이크 권한 설정 → 허용 → 다음
4. 카메라 화면에서 얼굴·목·조명 셀프 확인 3개 선택 → 시작
5. 시작 5초 뒤 테스트 흡인 알림 (매 식사 한 번)
6. 알림 확인 → 2초 발성 녹음 (움직이는 파형·타이머·진행 바) → 녹음 정리 → 완료 확인
7. 식사 모니터링 종료하기 → 해당 식사 기록 저장 및 상세 보고서 바로 표시
8. 보고서 탭에서 날짜별 기록과 식사 종류 필터 확인

기기 현지 시간 기준 아침 05:00~10:59, 점심 11:00~16:59, 저녁 17:00~21:59, 나머지 시간에는 간식을 기본 선택합니다. 새 준비 화면 진입 시 현재 시간을 다시 확인하며, 카메라 확인 화면에서 돌아오면 직접 고른 식사를 유지합니다.

파형은 녹음이 시작될 때 움직이고 종료·중단 시 멈추는 녹음 상태 애니메이션입니다. 실제 음량 측정 파형은 아닙니다. 기기의 동작 줄이기 설정이 켜져 있으면 반복 움직임을 생략합니다.

발성 녹음은 건너뛸 수 있습니다. 종료 버튼을 누르면 기록을 저장하고 해당 식사의 보고서를 바로 엽니다. 더보기에서 이름·글자 크기를 변경하고 식사 기록을 삭제할 수 있습니다.

## 데이터와 구현 범위

- 카메라: 전면 미리보기. 사진·영상 저장 없음.
- 마이크: 사용자가 시작한 2초 발성만 실제 녹음. 기기 임시 캐시에 생성되며 서버 전송·영구 보관·재생 UI 없음.
- 기록: 실제 세션 시간, 테스트 알림 횟수, 완료된 발성 녹음 횟수. 새 식사 기록에는 밀리초 단위 세션 길이와 알림 발생 오프셋도 저장합니다.
- 타임라인: 식사 시작·종료 사이에 알림을 시간 비율로 배치하며, 점 또는 알림 목록을 누르면 시각을 확인합니다. 예전 기록은 유지하며 시각 정보가 없으면 점을 임의로 표시하지 않습니다.
- 이름·요약·글자 크기 설정: AsyncStorage에 저장. 요청에 따라 기존 프로토타입 데이터는 이번 업데이트의 첫 실행에서 한 번 초기화합니다. 이후 새로 입력한 이름과 기록은 유지합니다.
- AI: 미연결. 실제 삼킴 횟수는 `—`로 표시합니다. 반복 설명은 제거하고 첫 시작 화면과 홈에만 “흡인은 테스트이며 아직 백엔드와 연동이 안돼요”를 표시합니다.
- 녹음 정리 로딩은 UI 전환이며 AI 분석이 아님. 정상/흡인 여부를 판정하지 않음.
- 모바일 백그라운드에서는 카메라를 해제하고 진행 중 녹음을 중단.
- 알림 설정·문의하기는 현재 기능 범위를 안내하며, 푸시 알림과 문의 서버는 미연결.

## 코드 구조

- `src/app/`: Expo Router 화면 경로와 루트 레이아웃
- `src/screens/Screens.tsx`: 각 화면
- `src/components/`: 공통 UI, 하단 탭, 팝업, 디자인 토큰
- `src/state/AppState.tsx`: 장치 권한, 세션·녹음 수명주기, 기기 저장
- `tests/flow.test.tsx`: 장치와 라우터를 모의한 사용자 흐름 통합 테스트

## 검증

```sh
npm run lint
npm run typecheck
npm test
npm run build:web
```

자동 테스트는 두 가지 동의, 권한 거절, 셀프 확인, 5초 알림, 2초 녹음, 종료 후 즉시 보고서 전환, 기록 저장·재조회·필터를 검증합니다. 실제 카메라·마이크 입력과 iOS/Android 설치 빌드는 실제 기기에서 별도로 확인해야 합니다.
